# 现网验证报告

**没有验证报告，就没有 H3 放行。** 一份"我测过了"的口头结论不算，要的是能事后对账的证据。

## 它是什么

把 P4 产出的 `dq_rules.json` 里的 `assert_sql`，拿到**生产库**上真跑一遍，逐条记录期望、实际、耗时、执行时点，落成：

- `需求开发员/交付/验证报告.json` —— 机器读，契约见 [`contracts/verification_report.schema.json`](../contracts/verification_report.schema.json)
- `需求开发员/交付/验证报告.md` —— 人读，一条规则一行

工具：[`tools/verify_live.py`](../tools/verify_live.py)

## 两种模式

| 模式 | 命令 | 产物 | 能不能当放行依据 |
|---|---|---|---|
| 离线 | `python tools/verify_live.py --req <需求目录> --offline` | 12 条 `skip`，`summary.verdict = pending` | **不能**，只是待执行清单 |
| 在线 | `set HQL_CMD=beeline -u jdbc:hive2://… -e` 然后 `python tools/verify_live.py --req <需求目录> --engine hive --dt 20261127` | 每条 `pass` / `fail` + 证据 | 能，但要 `fail = 0` 且有人签 `signoff` |

离线的产物故意写成 `pending`，而不是"看起来通过"：一份没有证据的报告比没有报告更危险——它会被当成证据用。

## 三种签署，不是两种

没有现网连接不等于没有纪律。签署状态只有三种，含义完全不同：

| `signoff.status` | 什么时候用 | 能不能进生产 | 必须附带 |
|---|---|---|---|
| `pending` | 离线清单，12 条全 `skip` | **不能** | 无（它就是个待办） |
| `waived` | **有条件放行**：方法论/预研阶段确实没有现网连接，但要留下"谁在什么条件下担了这个责" | 只能进测试环境 | `waiver.reason`（≥10 字）、`waiver.expires_at`（到期日）、`waiver.followup_todo` |
| `passed` | 现网跑过，`fail = 0` | 能 | 每条 check 的 `evidence`（执行时点 + 目标库 + 输出末行） |

`waived` 是这套方法论对"我只是写一套方法论、拿不到生产连接"的正式回答：**不假装通过，也不让流程卡死**。
命令：

```bash
python tools/verify_live.py --req 画像标签需求20261122 --offline --waive \
  --reason "方法论阶段没有现网连接，证据待接入后补" \
  --until 2026-12-12 --followup T-20261128-04 --by nino
```

三条约束写死在代码与巡检里：

1. `--waive` 不给 `--reason`（≥10 字）或 `--until`，直接拒绝——豁免必须有人、有理由、有到期日；
2. 到期未补证据，巡检把这条需求重新记为"未放行"（不是"过期提醒"）；
3. `verdict` 仍是 `pending`——豁免改的是**签署**，不改**证据**。任何人看报告第一眼都应看到"0 条真跑过"。

## 三条纪律

1. **验证 SQL 就是 DQ 的 SQL**。不另写一份"验证用"的查询，否则规则改了、验证没改，两边永远对不上。
2. **连接串不进仓库**。引擎命令走环境变量 `HQL_CMD`，目标库名走 `--target` 或 `HQL_TARGET`。
3. **失败不许绕过**。任何一条 `fail` 都不许上线；要么修数据，要么改规则再跑一遍（改规则要重走 P4 的门禁）。

## 一条 check 长什么样

```json
{
  "id": "V003",
  "rule_id": "DQ-005",
  "category": "null",
  "sql": "SELECT COUNT(1) FROM dws_user_profile_df WHERE dt='${dt}' AND is_repurchase='未购' AND order_cnt_30d<>'0'",
  "expect": "{\"type\": \"zero_rows\"}",
  "actual": "actual=0",
  "verdict": "pass",
  "evidence": "2026-11-28T10:55:00+08:00 耗时 41s｜prod-hive｜输出末行: 0"
}
```

`expect` 支持的判定：`zero_rows`（应为 0 行）、`zero_value`（应为 0）、`ratio_le`（绝对值 ≤ 阈值）、`min_rows`（≥ 下限）、`rerun_equal`（两次执行结果一致，用于幂等验证）。

## 缺什么

- 还没有真实的现网连接（本机没有 beeline / 数仓客户端），所以目前只有离线清单 + `waived` 的有条件放行；
- **接入方的责任**：`HQL_CMD` + `HQL_TARGET` 由有生产权限的人给，方法论只规定"证据长什么样、谁能签、到期怎么办"。
  没有这条连接时，P6 的交付物就是 `pending + waived`，不是"已验证"。
