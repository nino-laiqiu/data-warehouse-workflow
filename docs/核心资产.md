# 核心资产

这个仓库的资产不是"代码"，是**九样能独立演进、又互相咬合的东西**，加上一个底座。判断一个数仓工作流是否真的在运转，看这九样有没有人维护、有没有判据、有没有校验命令——而不是看仓库有多少文件。

| # | 资产 | 在哪 | 谁维护 | 判据（怎么算没坏） | 校验命令 |
|---|---|---|---|---|---|
| 0 | **业务本体**（底座） | `ontology/` | 人（唯一写入者） | 每个指标能追到口径、引用不打空、无重复 id | `python ontology/schema/validate.py` |
| 1 | 双轨工作流 | `flow/pipeline.yaml`、`flow/gates.yaml` | 需求分析员牵头 | 13 个 stage 都有 agent 与 skills；G0–G6 有可执行判据 | `python tools/check_skills.py` + `python tools/inspect.py` |
| 2 | 智能体 agent | `agents/roles.json`、`agents/*.md`、`需求开发员/prompts/` | 需求分析员 | 编制=5；开发者 1/2 互不可见；只有人能写本体 | `python tools/check_agents.py` |
| 3 | skills | `skills/sk-*/` | 技能归属人（见 SKILL.md `owner`） | 每个有 SKILL.md + schema + 校验器；调用关系只在 pipeline 里声明 | `python tools/check_skills.py` |
| 4 | wiki（LLM 知识库） | `knowledge/wiki/`、`knowledge/index.md`、`knowledge/index/chunks.jsonl` | 全员可写，追踪者登记 | 链接可解析；改老口径有影响分析 + 登记行 | `python tools/check_wiki.py` + `python tools/wiki_impact.py --check` |
| 5 | 记忆 | `memory/decisions/`、`memory/rulings/`、`memory/reviews/`、`memory/lessons/` | 全员可读，决策由人写 | 每个 ADR 有背景/决定/理由/代价；只增不改 | 人工评审（周报里过一遍） |
| 6 | 追踪 | `需求开发员/journal.jsonl`、`contracts/journal_entry.schema.json` | 追踪者 | 六类事件齐全、必填不缺、无跨轨读取 | `python tools/journal.py check --req <需求目录>` |
| 7 | 定时任务 | `flow/schedule.yaml`、`tools/run_schedule.py` | 需求分析员 | 每个任务有 cron、命令、ok_exit、留痕；调度器在仓外 | `python tools/run_schedule.py --list` |
| 8 | 全局规范 | `docs/全局规范.md` | 人 | 12 条约定；违反项尽量有脚本拦 | `python tools/inspect.py` |
| 9 | 问答沉淀 | `db/schema_mysql.sql`、`data/qa/`、`知识候选/` | 追踪者归集，全员可转正 | 每条问答有 qa_id/session/turn；候选必须人审；转正后 index 有登记行 | `python tools/qa_mine.py` + `python tools/wiki_impact.py --check` |

## 底座：为什么本体单独算

九样里其余八样都允许"边用边改"，只有本体不行——它是口径的唯一事实源。口径一旦松动，wiki 里的例子、DQ 规则里的阈值、交付文档里的字典会同时失真，而且**不会报错**。

所以本体有两个特殊约束：

1. 只有人能改，任何角色（含需求分析员）只能提 `ontology_delta` 提案；
2. 改动必须带影响面（`impact`）与迁移方案（`migration`），见 [`contracts/ontology_delta.schema.json`](../contracts/ontology_delta.schema.json)。

## 资产之间的咬合

```
        本体(0)  ──口径──▶  wiki(4) ──示例/坑──▶  skills(3)
           ▲                                      │
           │ ontology_delta                        │ 被调用
           │                                      ▼
   需求分析员(2) ──契约──▶ 双轨工作流(1) ──产出──▶ 需求目录
                                 │
                      追踪(6) ◀──┘   ──▶ 记忆(5)
                                 │
                     定时任务(7) ─┘   全局规范(8) 约束全部
```

- **规范(8) 不产生内容**，只约束其他七样怎么写；
- **记忆(5) 存"为什么"**，wiki(4) 存"怎么写"，本体(0) 存"是什么"——三者分工见 [`ADR-0001`](../memory/decisions/ADR-0001-memory-as-architecture.md)；
- **追踪(6) 是横切**：每条流水线都写它，但它不判断对错；
- **定时任务(7) 是外挂**：仓内只留"什么时候该跑什么"，谁来 cron 由部署环境定（见 [`docs/调度.md`](调度.md)）。

## 什么时候该动哪一样

- 发现"同一个词两种算法" → 动本体(0)，别名/枚举补进去；
- 发现"新人总写错 JOIN" → 动 wiki(4)（写进踩坑），必要时补 skill(3)；
- 发现"门禁造假" → 动追踪(6)（留痕不可编辑）+ 规范(8)；
- 发现"流程没人走" → 先看是不是卡点太多（HITL 只许 3 个）或校验太慢，别急着加角色(2)。
