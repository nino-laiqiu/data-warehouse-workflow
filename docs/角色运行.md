# 角色怎么跑起来（运行载体 = DSH subagent）

一句话：**角色不是"写在 md 里的岗位说明"，而是一段能被 `subagent` 直接执行的提示词。**
定义在 `agents/roles.json`（机器可读），生成器是 `tools/role_prompt.py`，校验器是 `tools/check_agents.py`。

## 为什么不做成 DSH preset

DSH 的 agent preset 是"一个会话的人格与工具集"（bundle 里声明 `@deepseek-ai/dsh-agent-preset`，`plugins` 决定装哪些工具）。
我们这 11 个角色是**任务级**的：developer-1 和 developer-2 要并行、要互相看不见、跑完就退场。
把它们做成 11 个 preset 有三个代价：① 每个 preset 都要装一次 bundle，profile 里多 11 行插件；② `subagent` 没有"选 preset"的参数，preset 选了也没用；③ 角色会在同一次需求里切换，preset 换不了。

所以载体选 **subagent + 生成的提示词**：人格、边界、输入输出、硬规则，全部写在提示词里，一次生成、一次执行、可留痕。

## 怎么派活

```powershell
# 1) 先落下提示词（同时是"我真的这样派活"的证据）
python tools/role_prompt.py --role developer-1 --req 画像标签需求20261122 --write

# 2) 起一个 subagent，把提示词原文贴进 prompt，隔离靠 must_not_read
#    （orchestrator 用 subagent 工具，两个开发者同时起、互不等待）
```

`--json` 输出机器可读结构，编排脚本据此决定并发与顺序：

```json
{"role": "developer-1", "gate": "G2", "tools": ["read","write","edit","glob","grep","pwsh"],
 "must_not_read": ["requirements/画像标签需求20261122/需求开发员/developer-2/**"], "prompt": "..."}
```

## 11 个角色

| id | 阶段 | 门禁 | 一句话 |
|---|---|---|---|
| `orchestrator` | 全程 | 验门 | 只派活、验门、记账 |
| `requirement-translator` | P1 | G1 | 把原始需求消灭歧义成 8 段 |
| `chronicler` | 全程 | — | 只追加地记录对话/产物/门禁 |
| `developer-1` / `developer-2` | P2 | G2 | 双轨并行，互不可见 |
| `supervisor` | P3 | G3 | 三层比对，出裁决与 final |
| `ontology-admin` | 全程 | — | 唯一能写 `ontology/` 的人 |
| `quality-officer` | P4 | G4 | 质量规则（可执行、可判定） |
| `lineage-steward` | P5 | G5 | 血缘、调度、回滚 |
| `doc-writer` | P6 | G6 | 数据字典与口径变更说明 |
| `analyst-writer` | A1–A6 | GA1 | 取数分析，只读 SQL |

## 隔离怎么保证

- **规则层**：developer-1/2 的 `must_not_read` 互为对方目录，`tools/check_agents.py` 强制这条必须双向存在，删一条就报错。
- **产物层**：G2 要求两轨 SQL 的 sha256 **不相同**——如果两轨一模一样，说明有人偷看或都被同一份上下文带偏了。
- **记录层**：journal 里记的是 `actor`，跨轨读取会在"产物路径 vs actor 的 writes"对不上时暴露。

## 已知缺口

1. 提示词是"软约束"——模型仍然可能越界读文件。真硬隔离要在沙箱层做（每个 subagent 只挂载自己的目录），目前没做。
2. `agents/*.md` 只覆盖 6 个角色（散文卡片），其余 5 个只有 `roles.json` 里的结构化定义，`check_agents.py` 会提示但不算错。
3. 同一需求重派角色会覆盖 `prompts/<role>.md`，旧版本只留在 journal 里——需要"提示词版本对比"时得自己 diff。
