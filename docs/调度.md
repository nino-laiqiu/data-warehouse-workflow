# 调度怎么接（仓库零运行时，调度在外面套一层）

一句话：**仓库里只有一个零依赖执行器 `tools/run_schedule.py`，定时器是谁都行，换载体不改代码。**

## 为什么这么设计

`tools/inspect.py`、`tools/scan_requirements.py`、`tools/check_wiki.py` 都是"跑一次、出结果、退出码表意"的普通程序。
它们不需要常驻进程——常驻进程会带来部署、权限、日志、重启一堆事，而这套东西每周只跑几次。
所以调度器的职责被压到最小：**在某个时刻执行一条命令**。

任务清单只在一个地方：`flow/schedule.yaml`。

| 任务 | cron | 干什么 |
|---|---|---|
| `radar-daily` | `0 9 * * *` | 扫 `需求池/`，有新增/改动就写待确认清单（退出码 2 = 有结果） |
| `inspect-weekly` | `0 9 * * 1` | 全仓巡检，出门禁矩阵 + 健康分 + 问题清单 |
| `wiki-lint` | `30 9 * * 1` | wiki 链接体检 |
| `memory-review` | `0 17 * * 5` | 人工：写 `memory/reviews/<周>.md` |

## 三种载体

### 1 手动（现在就能用）

```powershell
python tools/run_schedule.py --list      # 看清单与上次结果
python tools/run_schedule.py --due       # 跑此刻到点的
python tools/run_schedule.py --all       # 全跑一遍（体检用）
python tools/run_schedule.py --task radar-daily --force
```

### 2 Windows 任务计划程序（本机最省事）

```powershell
schtasks /Create /TN "数仓-需求雷达" /SC DAILY /ST 09:00 /TR "cmd /c cd /d E:\ai\数据工程 && python tools\run_schedule.py --due"
schtasks /Create /TN "数仓-周巡检" /SC WEEKLY /D MON /ST 09:00 /TR "cmd /c cd /d E:\ai\数据工程 && python tools\run_schedule.py --due"
```

（`--due` 会自己判断该不该跑，所以两条任务共用同一个命令也不会重复执行。）

### 3 cron（Linux / 服务器）

```cron
# 每天 9:00 判断有没有到点的任务
0 9 * * * cd /srv/data-warehouse && python3 tools/run_schedule.py --due >> runs/schedule/cron.log 2>&1
```

### 4 DSH 定时（想让 agent 参与时）

DSH 自带的定时器适合"到点了让某个会话里的 agent 去做判断"，而不是"跑一个脚本"。
适合挂的只有一条：**周五的记忆晋升**（要读 journal、挑候选、写小结——这是判断，不是脚本）。

```
每天 09:00 → 提示词："跑 python tools/run_schedule.py --due，把结果摘要给我；有 FAIL 就说 FAIL 在哪"
每周一 09:05 → 同上（巡检）
```

## 结果留痕

每次执行写两份：`runs/schedule/<时间戳>-<task>.json`（完整 stdout/stderr 尾巴）与 `runs/schedule/index.jsonl`（一行一次，供 `--list` 显示"上次结果"）。
`runs/schedule/` 已入库（和 `runs/inspection/` 一样，是趋势基线）。

## 加一条任务

1. 在 `flow/schedule.yaml` 加一条（id / cron / command / ok_exit / output / owner / description）。
2. 如果有校验器，顺手加进 `tools/inspect.py` 的门禁列表——**两条链路都要覆盖**，否则巡检看不见它。
3. `python tools/run_schedule.py --task <id>` 手动跑一次，确认 ok_exit 写得对（比如需求雷达正常返回 2）。

## 失败怎么办

- 退出码不在 `ok_exit` 里 → 记 FAIL，`index.jsonl` 里留痕，`--list` 下次会显示 FAIL。
- 连续失败不会自动通知（没有告警通道），靠人看 `--list` 或巡检报告。
- 想加告警：在 `run_task` 返回后接一个 webhook/邮件，别改任务本身。

## 巡检的权限：只出报告

用户明确（m02157）：**巡检只出报告，不自动提需求、不自动改文件。**
所以 `tools/inspect.py` 全程只读：它跑校验器、读文件、汇总，唯一写的动作是往 `runs/inspection/` 放报告。
发现"缺 DML 校验器"这类缺口时，报告里列出来，由人决定要不要开需求——不自己提。
