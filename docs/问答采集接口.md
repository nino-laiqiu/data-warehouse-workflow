# 问答采集接口

> 状态：**接口已定，采集端待开发**。本文只定义"外部系统怎么把问答送进来"，不规定采集端长什么样——
> 采集端可以是这套 DSH 的 A 线、可以是别的问答系统、也可以是人工导出脚本。只要满足下面的契约，就算接上了。

## 一句话

**一条问答 = 一条 `qa_record`**。任何系统把这种记录送进 `qa_turn` 表，就完成了接入。怎么送有三种形态，选一种即可。

## 三种接入形态

| 形态 | 谁来做 | 现在能用吗 | 适合 |
|---|---|---|---|
| ① 批量文件 | 采集端导出 JSONL | ✅ 已有 `qa_store.py ingest --file` | 日终补数、历史回灌 |
| ② HTTP 批量 | 采集端实时/准实时 POST | ⬜ 待开发 | 在线系统边聊边送 |
| ③ 直接写库 | 采集端自己连 MySQL 写 | ⬜ 待开发（约定见下） | 采集端与库同机房、不想多一跳 |

三种形态的**载荷完全相同**（`contracts/qa_record.schema.json`），所以形态可以随时换，下游不用改。

## ② HTTP 批量（草案）

```
POST {base_url}/v1/qa:batch
X-Api-Key: <采集端密钥>
Content-Type: application/json
```

请求体见 `contracts/qa_ingest_request.schema.json`，示例 `data/qa/ingest_request.example.json`：

```json
{
  "version": "1",
  "source": "dsh-a-line",
  "records": [ { "qa_id": "Q20261128-0001", "ts": "2026-11-28T10:00:00+08:00", "...": "..." } ]
}
```

响应：

```json
{ "accepted": 1, "skipped": 0, "rejected": [ { "index": 2, "qa_id": "Q20261128-0003", "reason": "qa_id 已存在且内容不同" } ] }
```

| 状态码 | 含义 | 采集端该做什么 |
|---|---|---|
| 200 | 部分或全部成功 | 看 `rejected` 逐条处理，`skipped` 是幂等命中，不用管 |
| 400 | 载荷不合契约 | 停止重试，修数据 |
| 401 | 密钥错 | 停止重试，换密钥 |
| 409 | 同 `qa_id` 内容不同 | 不许改历史记录，用新 `qa_id` 重送 |

**幂等键是 `qa_id`**：同 id 同内容 = `skipped`，同 id 不同内容 = `rejected`。这样采集端可以无脑重试，不用自己记账。

## ③ 直接写库（约定）

采集端自己连库时，必须遵守：

1. 只写 `qa_session` 与 `qa_turn`，**不写** `qa_candidate`（候选是挖掘产物，不是采集产物）。
2. 只 `INSERT`，不 `UPDATE`、不 `DELETE`——问答记录是证据。
3. 字符集 `utf8mb4`（`utf8mb3` 会静默截断 emoji 与四字节生僻字）。
4. `qa_id` 由采集端生成，格式 `Q{YYYYMMDD}-{4位序号}`，**跨会话不重复**。
5. 先写 `qa_session`（`ON DUPLICATE KEY UPDATE turn_cnt = VALUES(turn_cnt)`），再写 `qa_turn`。

## 配置：库名与连接方式由使用方自定

代码不写死库名。可用环境变量（**连接串一律不进仓库**）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `QA_DB` | `.data/qa.db` | 本地 SQLite 镜像路径 |
| `QA_DSN` | 空 | MySQL 连接串，例如 `mysql://user:pass@host:3306/dbname` |
| `QA_DB_NAME` | `dw_qa` | 只给建库脚本用，库名改成什么都行 |
| `QA_TABLE_PREFIX` | 空 | 想加前缀（如 `qa_`）时用，多套系统共库时有用 |

自建 MySQL 与云 RDS 都可以：只要支持 MySQL 5.7+（需要 `JSON` 类型），库名表名无所谓，
`db/schema_mysql.sql` 里改一处库名即可。

## 待开发清单

| 优先级 | 事项 | 验收判据 |
|---|---|---|
| P0 ✅ | 批量文件 + 幂等 | 已有：重复导入 `skipped`，改内容被拒 |
| P1 | HTTP 批量接口（一个 POST + 一个 `--serve`） | 推 100 条 → `stats` 显示 100 轮；重推 → `accepted=0, skipped=100` |
| P2 | DSH A 线钩子：每轮问答结束推一条；断网落本地 outbox 后补传 | 拔网线问 3 轮，恢复后自动补齐，不重复 |
| P3 | PII 打码（手机号/身份证/邮箱正则 + 姓名词典） | 送带手机号的问题进去，库里查不到明文 |
| P4 | 反馈回写（`feedback` / `feedback_note`） | 分析师点"没用"能在 `stats` 里看到下降 |

P1 的代码位置建议 `services/qa_ingest/`（独立进程，不塞进 `tools/`——它会长期跑，不是一次性脚本）。

## 红线

1. **接口不做业务判断**。它只负责"合规地存下来"，不做去重以外的清洗、不猜意图。
2. **不改历史**。发现历史记录错了，只能补一条更正，不能改原文。
3. **连接串与密钥不进仓库**（`.env` 已在 .gitignore）。
4. **采集失败不能拖垮问答**。A 线提问时不因为"存不进库"而报错，落 outbox 后补传。
