# 02 度量与指标

## 1. 先分清两个词，不然索引都建歪

| | 度量（measure） | 指标（metric） |
|---|---|---|
| 是什么 | 明细行上可以直接加总的**数值** | 度量 + 口径 + 计算方式，能回答一个业务问题 |
| 例子 | `pay_amt` = 199.00 | GMV = 已支付、按支付时间归日、不含运费、退款不回冲 |
| 存在哪 | 表字段（`dwd_pay_flow_di.pay_amt`） | `ontology/metric/`（有 id、有 owner、有反例） |
| 能加吗 | 能（同口径下） | 要看加性，见第 3 节 |

一句话：**度量是原料，指标是菜谱**。把原料当菜谱卖，就是"我给了你 `pay_amt` 字段，你自己看着办"——口径必然发散。

## 2. 常用度量清单

来自本体的过程（`ontology/process/`）与明细表字段：

| 度量 | 字段 | 来源表 | 说明 |
|---|---|---|---|
| 下订单数 | `M_ORDER_CREATE_CNT` | `dwd_order_main_di` | 按下单时间计，含未支付 |
| 下单金额 | `M_ORDER_CREATE_AMT` | `dwd_order_main_di` | 应付金额，含运费 |
| 支付金额 | `M_PAY_AMT` | `dwd_pay_flow_di` | 实付金额，**不含运费** |
| 支付笔数 | `M_PAY_CNT` | `dwd_pay_flow_di` | 按 `(order_id, pay_seq)` 去重后的笔数 |
| 退款金额 | `refund_amt` | `dwd_refund_di` | 按退款成功时间归日 |
| 商品件数 | `qty` | `dwd_order_item_di` | 件数，不是订单数 |
| 运费 | `freight_amt` | `dwd_order_main_di` | 单独存，便于"含运费/不含运费"两种口径切换 |
| 优惠金额 | `discount_amt` | `dwd_order_main_di` | 平台券 + 店铺券合计 |

> 度量只描述"一行里有什么数"，不描述"这些数怎么滤"。滤条件属于指标。

## 3. 加性：三种，混了必错

| 类型 | 含义 | 例子 | 汇总方式 |
|---|---|---|---|
| 可加（additive） | 任何维度上都能直接 SUM | GMV、支付件数 | `SUM(x)` |
| 半可加（semi-additive） | 某些维度能加，时间上不能 | 库存、账户余额 | 取期末值 / 取日均值再平均 |
| 不可加（non-additive） | 任何地方都不能直接 SUM | AOV、退款率、转化率 | **分子分母分别汇总后再相除** |

## 4. 常用指标

| 指标 | 公式 | 加性 | 最容易犯的错 |
|---|---|---|---|
| GMV | `SUM(pay_amt)`，按 `pay_time` 归日 | 可加 | 用 `create_time` 归日 → 把未付款订单算进成交 |
| 支付订单数 | `COUNT(DISTINCT order_id)`，支付成功 | 可加 | 用 `COUNT(1)` → 重复支付回调导致虚高 |
| 支付件数 | `SUM(qty)` | 可加 | 与订单数混淆，件单价算错 |
| 支付用户数 | `COUNT(DISTINCT user_id)` | **不可跨天加** | 7 天 UV ≠ 7 个日 UV 相加 |
| 客单价 AOV | `GMV / 支付订单数` | 不可加 | 对日 AOV 求平均 → 小店铺被过度加权 |
| 件单价 | `GMV / 支付件数` | 不可加 | 同上 |
| 退款率 | `SUM(refund_amt) / SUM(pay_amt)` | 不可加 | 单日可能 >100%（跨期退款），不是数据错误 |
| 支付转化率 | `支付订单数 / 下单订单数` | 不可加 | 分子分母取了不同的时间口径（一个按日、一个按周） |
| 动销率 | `有销量 SKU 数 / 在架 SKU 数` | 不可加 | 分母用了"历史所有 SKU"而非"当日可售" |
| 复购率 | `期内支付≥2次用户数 / 期内支付用户数` | 不可加 | 用订单数代替用户数 |
| 连带率 | `支付件数 / 支付订单数` | 不可加 | 与件单价是倒数关系，别混 |
| 加购率 | `加购人数 / 访问人数` | 不可加 | 分母用 PV 而非去重人数 |

## 5. 三条硬规则

1. **比率永远重算**：任何 `_rate` 字段跨维度汇总时，都要回到分子分母。`AVG(click_rate)` 是一个几乎总是错误的写法。
2. **去重计数不能二次相加**：日 UV 相加得到的是"人次"，不是"人数"。真要算周 UV，回明细 `COUNT(DISTINCT user_id)`，或预存 bitmap（Hive 用 `bitmap_union`）。
3. **口径冲突回本体**：如果你在 wiki 或 SQL 里发现两个不同的 GMV 定义，不要在这里裁决——提 `ontology_delta`，让本体管理员改 `ontology/metric/atomic/gmv.yaml`。wiki 只做索引，不做裁判。
