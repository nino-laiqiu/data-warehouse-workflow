# 01 命名与词根

## 1. 表名：`<层>_<域>_<实体>_<粒度>`

| 位置 | 取值 | 说明 |
|---|---|---|
| 层 | `ods` `dwd` `dws` `ads` `dim` `tmp` | tmp 表必须带日期，且不跨天存活 |
| 域 | `trade` `user` `item` `mkt` `log` | 一个域内不出现第二个同义域（如 `goods` 与 `item` 只能选一个） |
| 实体 | `order` `order_item` `pay_flow` `refund` `sku` | 用业务名词，不用缩写堆叠 |
| 粒度 | 见下表 | 粒度是整个表名里唯一必须"准确"的部分 |

粒度后缀：

| 后缀 | 含义 | 举例 |
|---|---|---|
| `_di` | 日增量：只存当天新增/变化的事件，一行一个事实 | `dwd_order_main_di` |
| `_df` | 日全量快照：每天存一份当天全量状态 | `dim_user_df` |
| `_hi` | 小时增量，分区 `dt` + `hh` | `dwd_user_behavior_hi` |
| `_1d` | 按天汇总（周期为 1 天） | `dws_trade_channel_1d` |
| `_7d` / `_1m` | 按周 / 月汇总 | `dws_user_active_7d` |
| `_td` | 累计至今（to date） | `ads_shop_gmv_td` |

**反例**：`dwd_order`（没说粒度）、`dws_order_1d_di`（两个粒度后缀打架）、`dwd_trade_order_info`（`info` 是废话，占长度不传递信息）。

## 2. 字段名：`snake_case` + 词根

禁止拼音（`yonghu_id` 是错的）、禁止驼峰、禁止无意义前缀（`col1`、`flag`、`val`）。

### 对象词根（名词，单数）

| 词根 | 含义 | 常见搭配 |
|---|---|---|
| `user` | 用户 | `user_id`、`user_type` |
| `order` | 订单 | `order_id`、`parent_order_id` |
| `item` / `sku` | 商品 / 最小库存单元 | `item_id`、`sku_id` |
| `shop` | 店铺 | `shop_id` |
| `category` | 类目 | `category_id`、`cate_l1_id` |
| `channel` | 来源渠道 | `channel_id`（值域见 `ontology/dict/channel.yaml`） |
| `pay` | 支付 | `pay_id`、`pay_time` |
| `refund` | 退款 | `refund_id`、`refund_amt` |
| `cart` | 购物车 | `cart_id` |
| `coupon` | 优惠券 | `coupon_id` |

### 动作词根（事件，过去式）

`create` `pay` `ship` `complete` `cancel` `refund` `visit` `collect` `add_cart` `share`
出现在过程表/行为表里，通常是 `is_<动作>` 或 `<动作>_time`。

### 度量词根（数值）

| 词根 | 含义 | 单位 | 能否直接 sum |
|---|---|---|---|
| `_amt` | 金额 | 元（`decimal(18,2)`） | 能（同币种、同口径） |
| `_cnt` | 笔数 / 次数 | 笔 | 能（但 `distinct` 计数不能） |
| `_qty` | 件数 / 数量 | 件 | 能 |
| `_rate` | 比率 | 0–1 的小数，不是百分数 | **不能**，必须分子分母重算 |
| `_dur` | 时长 | 秒 | 能（但平均时长不能对日均值再平均） |
| `price` | 单价 | 元 | 不能 |
| `stock` | 库存 | 件 | 不能（快照量，加总无意义） |

### 修饰词根

`is_`（布尔，tinyint 0/1）、`has_`（是否存在关联）、`first_` / `last_`（首末次）、`src_`（来源系统）、`origin_`（原始值，未清洗）、`dt`（分区日期）。

## 3. 类型与格式约定

| 类型 | 约定 | 理由 |
|---|---|---|
| 主键 / 各类 id | `STRING` | 业务 id 常溢出 bigint（雪花 id 19 位），且可能带前缀 |
| 金额 | `DECIMAL(18,2)`，单位**元** | 用 double 会出现 `0.1+0.2≠0.3`，对账必炸 |
| 时间 | `STRING`，`yyyy-MM-dd HH:mm:ss` | Hive 下 `date/timestamp` 跨引擎行为不一致 |
| 分区 | `dt STRING`，`yyyy-MM-dd` | 不用 `yyyymmdd`：`SUBSTR` 更好写，人眼更好读 |
| 布尔 | `TINYINT` 0/1 | 不用 `'Y'/'N'`：后者做 `SUM` 要 `CASE` |

## 4. 三个反例（真实踩过）

- **`amt` 和 `cnt` 混用**：`order_amount` 存的是笔数，只有看注释才知道。词根存在的意义就是让名字自解释。
- **用 `status` 一个字段表达三件事**：`is_paid`、`is_shipped`、`is_refunded` 是三件独立的事，拼成一个 `status` 枚举后，"退款中的已发货订单"就查不出来了。
- **拼音 + 缩写叠加**：`ddje`（订单金额）、`yhid`（用户 id），除了作者没人能读懂，LLM 也不行。
