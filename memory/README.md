# memory/ —— 长期记忆（记忆的"事实"部分）

知识库记的是**怎么做**，记忆记的是**我们做过什么、为什么这么定**。

## 和 `runs/` 的区别

| | `runs/` | `memory/` |
|---|---|---|
| 生命周期 | 单次运行，可删 | 长期，只增不改 |
| 内容 | 中间产物、门禁报告、指纹 | 决策、裁决、结论 |
| 粒度 | 每条 SQL、每份报告 | 每条决策一行结论 |

一次 run 结束后，只有**值得记住的结论**才升级进 `memory/`。全量留着等于没记忆。

## 放什么

| 目录 | 内容 | 谁写 |
|---|---|---|
| `decisions/` | ADR：技术选型与架构决策，含被否方案与原因 | 人 + orchestrator |
| `rulings/` | 口径裁决：争议指标最终怎么定、依据是什么 | 本体管理员 |
| `reviews/` | 评审结论：H1/H2/H3 的结论与豁免 | 评审人 |
| `lessons/` | 复盘：出过错的地方，指向 `knowledge/04_踩坑/` | quality-officer |

## ADR 格式

```
decisions/ADR-0001-<短标题>.md
```

```markdown
# ADR-0001 采用双泳道而不是单一流水线

- 状态：已采纳
- 日期：2026-11-22

## 背景
...

## 决策
...

## 被否方案
- 单一 8 段流水线：分析师被 8 道门禁挡住，会绕开系统直接找开发写 SQL。

## 后果
- 需要维护两套门禁配置。
```

## 硬规则

1. **只增不改**。判断错了，追加一条"ADR-0007 推翻 ADR-0001"，不要改原文。
2. **一条决策一文件**，不要写日记。
3. **被否方案必须写**。只写结论的记忆没有价值——下次还会有人提同样的方案。
