# sk-spec-align — 定稿口径与产物的对齐复核

> 状态：**只有规格，没有实现**。本文定义"这个技能存在、什么时候被调用、凭什么算过"。
> 实现时要补：`schema.json`（输入输出契约）、`validate.py`（判据代码化）、至少 3 条正反用例。

## 什么时候被调用

定稿口径被修改之后（G3_recheck 触发），或有人问 这版跟需求还一致吗

## 输入

定稿需求文档 + 现有产物（SQL / DQ / 字典）

## 输出

对齐表：每条口径 一致|已改|保留偏差（偏差要写原因与回切条件）

## 判据（怎么算过）

- 口径逐条对照，不许抽样
- 标为一致的必须能在 SQL 里指到具体实现
- 保留偏差必须有跟进待办

## 失败怎么处理

发现偏差但既不改也不记录 → G3_recheck 直接失败

## 不做什么

不替开发者改实现；不重写需求
