# sk-sql-diff — 两轨 SQL 的语义差异分析（只描述，不判决）

> 状态：**只有规格，没有实现**。本文定义"这个技能存在、什么时候被调用、凭什么算过"。
> 实现时要补：`schema.json`（输入输出契约）、`validate.py`（判据代码化）、至少 3 条正反用例。

## 什么时候被调用

B 线 P3 第一件事，早于裁决

## 输入

track-1 SQL + track-2 SQL + 定稿口径

## 输出

差异清单：每条给 层面(口径|结构|实现) / 两轨原文位置 / 影响（行数、口径、性能）/ 依据

## 判据（怎么算过）

- 差异必须覆盖语义层，不能只比字符串
- 每条差异必须能指到具体行
- 不许出现 哪个更好 的判断
- 口径差异必须回指需求文档条文

## 失败怎么处理

两轨完全相同 → 报隔离失效，而不是报无差异

## 不做什么

不做裁决、不改 SQL
