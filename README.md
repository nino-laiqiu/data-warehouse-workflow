# 数仓智能开发工作流

用「业务本体 + LLM 知识库 + Skills + Agents」把数仓开发从"写 SQL"变成"可校验的流水线"。

- 目标平台：Hive 3.x / Spark SQL 3.x
- 建模方法论：Kimball 维度建模 + OneData 原子/派生指标
- 首个样板域：手机 Push 推送数据

## 两条泳道

| | A 线：取数分析 | B 线：数仓开发 |
|---|---|---|
| 使用者 | 数据分析师、运营、业务方 | 数仓开发工程师 |
| 起点 | 一个业务问题 | 一个数据需求 / 指标上线 |
| 耗时 | 分钟级 | 天级 |
| 门禁 | GA1~GA3（轻） | G1~G8（重） |
| 产物 | SQL + 结论 + 口径说明 | 表 + 指标 + 血缘 + 文档 |

两条线共享同一份本体与知识库（约 80%），分化在起点、门禁强度与产物形态（约 20%）。
连接点是**晋升机制**：A 线的高频问题 → 指标化提案 → 进入 B 线固化。

| 目录 | 职责 | 一句话 |
|---|---|---|
| `ontology/` | 对象 / 过程 / 指标 / 关系 / 约束 | 唯一事实源，口径只在这里定义 |
