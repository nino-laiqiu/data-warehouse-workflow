## 1. 一句话目标

每天产出一张用户画像宽表 `dws_user_profile_df`，一个用户一行、13 列，覆盖基础画像（5 个标签）与购买行为画像（7 个标签）+ 用户 id，供运营圈人与下游分析直接按标签过滤。

## 2. 口径

| 标签 | 列名 | 取值 | 口径来源 |
|---|---|---|---|
| 性别 | `gender` | 男 / 女 / 未知 | 用户资料 |
| 年龄段 | `age_band` | <18 / 18-24 / 25-34 / 35-44 / 45+（周岁，生日当天进新档） | 用户资料生日 |
| 城市等级 | `city_level` | 一线 / 新一线 / 二线 / 三线及以下 / 未知 | 最近一次收货地址所在城市，缺失回退注册地 |
| 注册渠道 | `register_channel` | `CHANNEL` 枚举（app / mini_program / h5 / pc） | 本体 `CHANNEL` |
| 注册距今天数 | `register_days_band` | 0-30 / 31-90 / 91-180 / 180+ | 注册时间 |
| 是否复购 | `is_repurchase` | 是 / 未购 | 终身（历史上付过款即「是」） |
| 近 30 天订单数 | `order_cnt_30d` | 0 / 1 / 2 / 3+ | 本体 `ORDER_CNT` |
| 近 30 天 GMV | `gmv_30d` | 金额，两位小数 | 本体 `GMV`（按 pay_time 归日、不含运费、退款不回冲） |
| 客单价档位 | `aov_band` | <50 / 50-100 / 100-300 / 300-1000 / 1000+（左闭右开） | 本体 `AOV`（SUM/SUM，禁止 AVG(日客单价)） |
| 最近支付距今天数 | `last_pay_days` | 整数天 / 未购 | 支付时间 |
| 首单距今天数 | `first_order_days` | 0-7 / 8-30 / 31-90 / 90+ | 首笔支付时间 |
| 偏好品类 | `preferred_category` | 一级类目 id / 无偏好 | 近 30 天支付金额 Top1，并列取类目 id 最小 |

时间窗统一按 `[dt-N, dt-1]`，**不含当天**（当天数据不全，含进去每天都会变）。N=30 时指 `[dt-30, dt-1]`。

## 3. 输入表与字段

| 表 | 用途 | 关键字段 |
|---|---|---|
| `dim_user_df` | 用户主档（SCD2，取 `rn=1` 当天有效行） | `user_id`、`gender`、`birthday`、`city_level`、`register_time`、`register_channel`、`is_test` |
| `dwd_pay_flow_di` | 支付流水，算 GMV/订单数/客单价/首单/最近支付 | `user_id`、`order_id`、`pay_time`、`pay_amt`、`dt` |
| `dwd_order_item_di` | 订单明细，算偏好品类 | `order_id`、`category_id_l1`、`pay_amt`、`dt` |
| `dim_category_df` | 类目维表，取一级类目名 | `category_id`、`category_id_l1`、`category_name_l1` |
| `dws_user_profile_df` | 自身，用于 DQ-010 的昨日对比 | `user_id`、`first_order_days`、`dt` |

过滤：`dwd_pay_flow_di.is_pay = 1`、`dim_user_df.is_test = 0`（测试账号规则见 Q10）。

## 4. 输出表

`dws_user_profile_df`（分区 `dt`，ORC + SNAPPY，13 列全 COMMENT）：

```
dt, user_id,
gender, age_band, city_level, register_channel, register_days_band,
is_repurchase, order_cnt_30d, gmv_30d, aov_band, last_pay_days,
first_order_days, preferred_category
```

每日全量快照，行数 = 当日 `dim_user_df` 去重用户数。

## 5. 口径边界

- **未购**：所有购买类标签写"未购"，与"未知"（资料缺失）严格区分——两者都表示"没数"，但原因不同，运营话术不同。
- **缺失值**：数值型标签缺失落 `0`，字符型落 `未知` / `未购`，不落 NULL（下游按字符串圈人，NULL 会被静默漏掉）。
- **退款**：GMV 不回冲（按支付时点计），退款率单独看，两者不平账属正常。
- **单日退款率可 >100%**：当日退款对应的是历史订单，分母小就会超 100%。

## 6. 验收标准

1. 行数 = 当日 `dim_user_df` 去重用户数，偏差 0；
2. `user_id` 唯一，重复行数 = 0；
3. 13 列**无 NULL**，NULL 行数 = 0；
4. 近 30 天 GMV 汇总值与 `ads_trade_metric_1d` 当天值偏差 < 0.01%；
5. `is_repurchase='未购'` 的行，`order_cnt_30d` 必须 = '0'（单向蕴含，违例行数 = 0）；
6. 与昨日快照比，`first_order_days` 档位只增不减（倒退行数 = 0）。

## 7. 不做什么

- 不做实时（T+1 全量）；
- 不做人群圈选服务（只产表，圈人由下游自己写 WHERE）；
- 不做标签权重/评分（只出原始档位）；
- 不覆盖 Push 域、不做跨域 ID 映射。
