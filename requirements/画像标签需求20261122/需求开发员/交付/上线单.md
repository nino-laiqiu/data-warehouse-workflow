## 三、上线步骤

1. **建表**：`hive -f 01_dws_user_profile_df.sql`、`hive -f 02_dim_tag_df.sql`
2. **灌字典**：`hive -hivevar dt=2026-11-22 -f 04_dim_tag_df_data.sql`（幂等，可重复执行）
3. **补历史分区（可选，仅补 7 天）**：对 `2026-11-15 … 2026-11-21` 逐日执行 ETL
4. **首跑**：`hive -hivevar dt=2026-11-22 -f 03_etl_dws_user_profile_df.sql`
5. **质检**：`hive -hivevar dt=2026-11-22 -f dq_check.sql`，逐条确认返回 `0`
6. **重跑幂等验证**：把第 4 步再执行一次，比对 DQ-011 的四个指纹（行数/用户数/GMV 合计/复购数）必须完全一致
7. **挂调度**：上传 `dag_dws_user_profile_df.py`，`catchup=False`，等待次日 03:00 首次自动运行
8. **通知下游**：运营平台 `ads_user_segment` 改读本表，需确认列名（`basic_*` / `purchase_*`）

## 四、上线后验证（T+1）

```sql
-- 1. 分区行数与当日用户数一致（DQ-006 的人工复核）
SELECT dt, COUNT(1) AS rows_per_dt
FROM dws_user_profile_df WHERE dt >= '2026-11-22' GROUP BY dt;

-- 2. 关键标签分布是否合理（UNKNOWN 不应超过 5%）
SELECT basic_gender, COUNT(1) FROM dws_user_profile_df
WHERE dt = '2026-11-23' GROUP BY basic_gender;

-- 3. 购买类标签分布
SELECT purchase_is_repurchase, purchase_last_pay_days, COUNT(1)
FROM dws_user_profile_df WHERE dt = '2026-11-23'
GROUP BY purchase_is_repurchase, purchase_last_pay_days;
```

## 五、回滚

按 `血缘/lineage.json` 的 rollback.steps 执行，要点：

- 只回退出问题的那个 `dt` 分区，不重建全表；
- 上游本身错 → 先重跑上游分区，再重跑本表再质检；
- 上游短期不可修 → 当日分区只保留 `user_id + basic_*`，购买类标签置 `未购`，并**通知运营平台当天不要用购买类标签圈人**；
- 回滚后必须重跑 `dq_check.sql` 并留存输出，口头的"应该好了"不算。
